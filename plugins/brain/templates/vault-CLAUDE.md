# Claude LLM-Wiki - vault schema

This vault is Claude's long-term memory, shaped as an Obsidian wiki. When you work anywhere inside `$CLAUDE_VAULT`, you are its maintainer. Follow this schema exactly. It overrides generic behavior for everything under this vault.

## Three-layer model
1. **sources/ are immutable.** Each file is a verbatim capture of something external: a URL, a repo doc, a local file. Never edit a source after it is written. Add a new capture instead.
2. **wiki pages are AI-maintained.** These are the synthesized, deduplicated notes you read, write, and reconcile. They cite sources and link to each other.
3. **this schema is the contract.** This CLAUDE.md tells you how to keep the wiki disciplined. Read it before you touch anything.

## Tree layout
The repository roots are listed in `~/.config/brain/config.json`. A vault is either solo or tiered.
- **Solo**: one repository, configured as `privateVault`. It holds everything, commonly in `wiki-me/projects/` and `wiki-me/life/`. `index.md`, `log.md`, `topics.yaml` and this file live at its root.
- **Tiered**: up to three sibling repositories under one parent folder, which is `$CLAUDE_VAULT`.
  - `personalVault` holds the user's own work knowledge that is not shared with the team, in `wiki-me/` and any team-private trees.
  - `sharedTree` holds shared team knowledge, commonly in `wiki-team/`. Contribute to it on a PR branch. Never push directly to its default branch.
  - `privateVault`, optional, holds non-work knowledge such as side projects and personal life, on a remote of the user's own and never on a work remote. Without one, non-work knowledge goes to a `life/` tree in the personal vault.
  - `index.md` sits at the parent and spans all roots. Each root keeps its own `CLAUDE.md`, `topics.yaml`, `log.md` and generated `MUSTKNOW.md`.
- In every root, `sources/` holds immutable captures, `attachments/` holds binary assets, and `digests/` holds weekly recaps.
- A root may carry `external-slugs.txt`, one slug per line, naming pages that live in another vault cloned only on some machines. Links to them are reported as external, not dead.

## Page frontmatter schema
Every wiki page opens with YAML frontmatter, then the body after the closing `---`:
```
---
title: <human title>
summary: <one line, shown in index.md and when the page is read. NOT injected into sessions>
sources: [<source filenames or refs>]
last_updated: YYYY-MM-DD
tags: [work]           # or [me, projects], [me, life], [public]
pin: false            # true ranks the page first among equal brain_lib.py find matches
must_know: <optional. one imperative line, or a list of them, injected verbatim into every session>
---
```

Quote any value that contains a colon followed by a space, or a backslash. An unquoted one breaks the YAML, and a page with broken frontmatter is skipped silently by every rebuild.

`must_know:` is the always-on tier. The admission test is narrow: add a line only when a session that does not apply it unprompted produces wrong output. It prevents an error, it does not merely inform. One fact means one line, and a corollary of an existing rule belongs in that page body. Each line is at most 160 characters, and the cap across all roots is 30 lines.

## Linking and citation
- Cross-link concepts with `[[slug]]`. Slugs are globally unique, hyphenated, and have their type prefix stripped.
- Cite the backing source inline with `[[source: <YYYY-MM-DD>-<slug>.md]]`.
- Prefer a link over repeating a fact. One concept lives on exactly one page, and other pages link to it.

## Operations
Seven skills maintain this vault. They all read `$CLAUDE_VAULT`, so they run from any working directory.
- **brain-capture** ingests a URL, file, or repo doc into `sources/`, then optionally synthesizes a wiki page.
- **brain-sync** validates frontmatter, fixes dead links, and merges overlapping pages non-destructively.
- **brain-lint** is a read-only integrity check: frontmatter, dead links, orphan pages, unique slugs, gloss coverage, must-know size, and a hard secrets scan. Add `--fix` for safe fixes only.
- **brain-digest** is the weekly synthesis. It diffs recent changes, re-pins hot pages, demotes stale ones, and writes a dated digest.
- **brain-graduate** distils durable knowledge from completed journals into the appropriate vault page.
- **brain-freshness** checks configured sources and refreshes knowledge that has changed.
- **brain-contribute** opens a pull request for changed shared-tree pages. It applies only to a tiered vault.

## Sensitivity rules
- Never put employer-confidential or personal-life content into `wiki-public`. When in doubt, keep it in a private tree.
- Never write secrets, credentials, tokens, passwords, or private keys into the vault. Capture the knowledge and redact the secret.

## Auto-generated files
- `MUSTKNOW.md` and `index.md` are generated by `brain_lib.py rebuild`. Do NOT hand-edit them. Change a page, then rebuild.
- Nothing lists the pages into a session. Finding a page is `brain_lib.py find <query>`, which searches slug, title, summary, tags and the folder's `topics.yaml` gloss, and groups hits under that gloss. Exact words on the page rank first, then word forms such as `verify` for `verification`, then pages found only through their folder's gloss. A `pin: true` page ranks first among equal matches. Add `--body` to search page text. `index.md` holds the full catalog for a direct read.
- `topics.yaml` at each root is hand-maintained source, not generated. It maps a wiki folder to its gloss, and a word in the gloss finds that folder's pages. Write a gloss as routing bait, naming what someone would search for. `brain-lint` fails on a folder with no gloss.
- `log.md` is an append-only operation log. Do NOT reorder or rewrite past entries.
